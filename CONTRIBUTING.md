# Contributing a profile

## 1. Make the profile in NumpadControl

Set the keys up in the app and try them. Then use **Profile ⋯ → Export profile…** to save the file.

## 2. Put it in your folder

```
profiles/community/<your-github-name>/<profile-name>.json
```

- **File name:** lower-case words joined by `-`, such as `davinci-resolve.json`.
- **Folder:** your GitHub user name, exactly. CI checks that it matches the account opening the pull request.

`python tools/nclib.py new <your-github-name> <profile-name>` creates the file with a `meta` block to
fill in. You can paste your exported `profile` object into it.

## 3. Add `meta`

Add this next to `format` and `version` (NumpadControl ignores it):

| Field | Required | |
|---|---|---|
| `author` | yes | your GitHub user name |
| `description` | yes | 10–500 characters: what it's for and what to set up first |
| `tags` | yes | 1–8 lower-case tags (`streaming`, `video-editing`, `gaming`…) |
| `platforms` | yes | any of `windows`, `linux`, `hyprland` |
| `requires` | no | things to set up, such as `"OBS WebSocket server on"` |
| `min_app_version` | no | oldest NumpadControl version it works with |
| `homepage` | no | an `https://` link (a video or a write-up) |

For completion in VS Code and other editors, also add
`"$schema": "../../../schema/profile.schema.json"`.

## 4. Make it work for other people

- **`match`:** list the app's Linux window class **and** its Windows program name without `.exe`, separated
  by commas, for example `obs,com.obsproject.Studio,obs64`. Matching ignores case.
- **Leave out things only your setup has**, such as OBS scene and source names, mode names, profile-set
  names, file paths, sound files and audio device names. If the profile needs them, say exactly what to
  create in `description`. The validator warns about each one.
- **Never include passwords or tokens**, for example in `type_text`, `copy_text` or `run_python`.
- **Explain every ⚠ action in the pull request.** These are `run_python`, `macro`, `press_keys`,
  `type_text`, `launch_app`, `open_path`, `open_url` and the power and lock actions. They aren't banned:
  `press_keys` is how most app profiles work. They just get a closer review.
- **Use Hyprland-only actions** (`hypr_float`, `hypr_scratchpad`) only with `"hyprland"` in `platforms`.
  Voice-changer actions are Linux-only.

## 5. Check and open the pull request

```sh
python tools/nclib.py validate            # errors must be fixed; read the warnings
```

Only change files in your own folder. `index.json` is regenerated by a maintainer after merging, so
pull requests don't conflict with each other. Changes to `tools/`, `schema/` or `.github/` are welcome
as a separate issue or pull request; CI marks those as needing a maintainer.

**Errors** mean NumpadControl would refuse or drop part of the file. **Warnings** make the profile less useful
to others. They don't block the pull request, but a reviewer may ask about them.

## Official profiles

`profiles/official/` is for profiles the maintainers keep working with each NumpadControl release. A
popular community profile can be promoted there with its author's agreement, keeping the author's name.

## Refreshing `schema/actions.json`

When NumpadControl adds or changes actions:

1. Update `schema/actions.json` from `numpadctl/actions.py` (ids, groups, params, and which actions are
   macro steps) and `numpadctl/profile_io.py` (limits). Also update `app_version` and the `source` commit.
2. Copy any new action ids into `$defs.action_id` in `schema/profile.schema.json`. The tests check that the
   two files agree.
3. Run the tests and `python tools/nclib.py index`.

## Maintainers: after merging profiles

```sh
python tools/nclib.py index && python -m unittest discover -s tests
```

Commit the new `index.json`. On `main`, CI fails while it is out of date.
